# Calculator → FerroUI compatibility tracker

Port policy: preserve the original Calculator source, reuse upstream FerroUI features, and track remaining fidelity work. **Do not implement missing framework features in this application.** A fallback is not evidence of rendering parity.

## Audited revisions — 2026-10-31

- Calculator: [`79e1ac53bba690cdf930e5dcd6ed9dbc4cbfb128`](https://github.com/microsoft/calculator/tree/79e1ac53bba690cdf930e5dcd6ed9dbc4cbfb128), the unmodified `upstream/calculator` submodule. All 775 original files, including the native C++ math engine, remain covered by the preservation manifest.
- **FerroUI main and application dependency:** [`62b4843106ac69d3769b2f8e3dd771837534b960`][main], pinned in Cargo.toml/Cargo.lock. This replaces the application's `934b9ce1` dependency and supersedes the 2026-10-23 audit of `61ad85c3`.
- Evidence: [materials implementation/deviations][materials], [composition inventory][composition], [native WinUI controls][controls], [Calculator compatibility plan][calculator-plan], and the linked implementation files. Several upstream planning/inventory tables and theme-deviation rows describe the pre-port state; current source registration and implemented-phase sections take precedence over those historical “missing” labels.
- [XAML adaptation inventory](xaml-adaptations.json) records translated/deferred members and restored error-state groups. `python3 scripts/port_xaml.py --check` verifies reproducibility.

The previous statements that Reveal, AcrylicBrush, NavigationView, ThemeShadow, alpha masks and all VSM support were missing are obsolete. NavigationView reached main through the W8 native-controls work; the status of the old umbrella PR #286 is no longer a test of API availability.

**Source fidelity note:** the pinned Calculator's modern CalcButtonStyle uses solid default/hover/pressed fills. Its App.xaml retains older Reveal recipes. The requested Reveal appearance is based on the [2019 Fluent CalcButtonStyle][calculator-reveal-template]: Margin=1, BorderThickness=1, RootGrid with a background replaced by the hover/press Reveal brush, and a ContentPresenter whose border uses AppControlForegroundTransparentRevealBorderBrush even when not hovered. The transparent border brush is lit across nearby keys; the border geometry confines it to the edges. Calculator declares no custom gap opacity mask. The earlier port's added keypad RevealBackplate overlay has been removed. Modern ControlCornerRadius (4 DIP) is now applied to both the root background and presenter border; a Border substitutes for the source Grid to clip the rounded background. Modern normal-state fill resources, key grids/names/IDs/glyphs and the C++ revision remain pinned; this is explicitly a source-version adaptation, not an identical copy of the modern template.

**Programmer radix correction:** the original `Views/CalculatorProgrammerOperators.xaml` uses full-width RadixButton/RadioButton rows, with a 3-DIP accent indicator column, a label column of at least 48 DIP and a value column. The port now uses grouped native RadioButtons and aligns all four values; BIN no longer has a narrower hit area. The source's PointerOver/Pressed states use SubtleFillColorSecondaryBrush/TertiaryBrush, not the keypad hover brush. Its separate RevealBackplate has only top/bottom borders. The port maps the SDK ListViewItemRevealBackground/BorderBrush aliases, absent from the audited theme dictionary, to the existing native SystemControlTransparentRevealBackgroundBrush/BorderBrush. No framework rendering substitute is introduced. Row minimum height is currently 36 DIP in the adapted wrapper; the original 12-DIP minimum, flexible row heights, max-height layout, copy context menu and custom RadixButton keyboard handling still need full adaptation.

## Materials, lights, shadows and composition

**MATERIAL-01 upstream fix prepared:** the border light's temporary Offset expression drops its live pointer/SpotlightHeight reference parameters, leaving its server position at (0,0,0). FerroUI commit `d7d24f23bea40cb6e535914605a812b8d0e5b660`, based on upstream main `f867314ba8fdb9fdfe29f2650dd3afc9820b684d`, retains the expression in BorderResources. Both new compositor regressions fail before the fix and all seven media tests pass after it, covering all four lights and material-policy recreation. [Exported patch](../patches/ferroui-reveal-border-light-lifetime.patch); worktree: `/Volumes/SSD/repos/FerroUI-reveal-border-fix`. The application dependency remains pinned pending upstream adoption; a local verification build uses that worktree through an external Cargo override. The failure recorded below describes the unpatched dependency.

**Patched-build verification:** the neighboring-edge pixel reproducer now passes in both light and dark themes, including with rounded key borders. Separate checks on an operator key and a numeric key verify pointer-dependent interior pixels, exact original hover/press brush colours, normal font weight and material-policy fallback. Radix checks cover equal row widths/value alignment, clicking the value area, group exclusivity, keyboard selection and the selected accent marker. These local Skia checks and the user's native visual confirmation do not certify Windows pixel parity.

**Native rendering follow-up:** the user subsequently reported that only the hovered key lit in the live window. The earlier capture checks missed a second framework bug: the server's light registry was thread-local, although native rendering can alternate between synchronous UI-thread frames and render-thread frames under the compositor lock. Lights created on one thread were invisible to the other. The worktree now stores weak light registrations on ServerCompositor and uses that registry for scene-lighting brushes, directly targeted lights and coordinate-space invalidation. The new cross-thread scene-lighting regression fails before this change; all 97 composition tests pass with the fix, including separate scene-lighting and targeted-light regressions. The Calculator edge check also covers 1x/2x display scaling. [Complete two-fix patch series](../patches/ferroui-reveal-lighting.patch) supersedes the first patch when starting from the unpatched base; the original lifetime-only patch remains available separately.

The registry fix is commit `a22094a4c487ee1b43d62e21e41b998c0f2176f2` in the same FerroUI worktree, with Wieslaw Soltes as both author and committer. [Registry fix only](../patches/ferroui-reveal-compositor-light-registry.patch) is available for a tree that already has the first fix. The rebuilt native macOS calculator retains the rounded keys and original Reveal recipes; the user confirmed that lighting now spreads across neighbouring borders near a key junction. Normal UI integration checks also pass against the two-fix build. The application's Git pin remains unchanged pending upstream adoption.

“Available” below means the framework API exists; it does not certify native WinUI pixel parity. Local verification and remaining platform limits are recorded in [PORTING.md](PORTING.md).

## Application work (not missing FerroUI features)

| ID | Item | Current state / reason |
|---|---|---|
| APP-01 | Graphing | Original source/interfaces preserved. Microsoft's proprietary graphing engine is not published; upstream has a mock. Graphing is visibly unavailable. Adapting its view and choosing an engine remain separate from the now-available shadow/mask APIs. |
| APP-02 | Currency | Exact original static fictional developer feed is connected and labelled mock. No invented exchange rates or claimed retail feed. A licensed live provider remains separate work. |
| APP-03 | Settings/session persistence | Appearance changes work during the session. Original settings/history/memory persistence and command snapshots are not implemented. |
| APP-04 | Clipboard/shortcuts | Existing async clipboard APIs, validated numeric paste and extracted keypad shortcuts are wired. Full platform/localized shortcut and announcement parity remains open. |
| APP-05 | Engine preservation | CalcManager/CEngine/Ratpack compile unchanged. Compatibility headers, UTF/ABI ownership and offline continuations remain outside upstream. UnitConverter retains its original double-based ratios; Calculator arithmetic still uses the original rational engine. |
| APP-06 | Fonts, icons and visual parity | Original CalculatorIcons.ttf is embedded unchanged and used for keypad symbols and navigation glyphs. Text uses the WinUI theme's Segoe UI Variable Text / Segoe UI / platform fallback chain; no Segoe family is installed on this Mac and no Segoe text font is bundled. Text shapes/metrics therefore remain a parity gap. History is still a text label, the theme toggle and memory dropdown include substitute characters, and the compact-overlay icon/action is absent. Restore those original icon controls, adaptive result/header typography, exact spacing and platform appearance before claiming visual parity. |

## Completion rules

Keep stable gap IDs. Record framework availability, application adoption and native visual/semantic verification separately. Link the exact upstream revision, and test supported platforms/backends before closing fidelity work. Source audits and local Skia captures do not certify Windows/WinUI pixel parity. Missing framework features remain upstream work; the Reveal fix is exported separately for upstream and the application uses native lighting.
